# Fix : score du reranker injecté dans metadata (bug LangChain #22556)

**Date** : 2026-04-30
**Status** : ✅ Implémenté
**Issue upstream** : [langchain-ai/langchain#22556](https://github.com/langchain-ai/langchain/issues/22556)
**Fichier** : `src/chain.py` — classe `ScoringCrossEncoderReranker`

---

## Le bug

`langchain.retrievers.document_compressors.CrossEncoderReranker` utilise les scores du cross-encoder pour **trier** les documents, puis les **jette** avant de retourner les documents :

```python
# Code upstream simplifié
def compress_documents(self, documents, query, callbacks=None):
    scores = self.model.score([(query, d.page_content) for d in documents])
    docs_with_scores = list(zip(documents, scores))
    result = sorted(docs_with_scores, key=operator.itemgetter(1), reverse=True)
    return [doc for doc, _ in result[:self.top_n]]  # ← le score est jeté ici
```

**Conséquence côté UI** : impossible d'afficher le score de pertinence aux utilisateurs.
Notre app affichait `score: 0.00` partout, ce qui :
- ne donnait aucune information à l'utilisateur sur la pertinence
- faisait croire à un bug de notre code (alors que le bug est upstream)
- masquait le fait que le reranker fonctionne pourtant correctement (le tri est bon)

---

## Le fix

Sous-classe `ScoringCrossEncoderReranker` qui injecte le score dans `metadata['relevance_score']` avant le slicing top_n :

```python
class ScoringCrossEncoderReranker(CrossEncoderReranker):
    def compress_documents(self, documents, query, callbacks=None):
        scores = self.model.score([(query, d.page_content) for d in documents])
        docs_with_scores = list(zip(documents, scores, strict=True))
        ranked = sorted(docs_with_scores, key=operator.itemgetter(1), reverse=True)
        result = []
        for doc, score in ranked[: self.top_n]:
            # Sigmoid : convertit le logit brut du cross-encoder en probabilité [0,1]
            doc.metadata["relevance_score"] = 1.0 / (1.0 + math.exp(-float(score)))
            result.append(doc)
        return result
```

Et dans `build_retriever()` :
```python
reranker = ScoringCrossEncoderReranker(model=_get_reranker_model(), top_n=RERANKER_TOP_N)
```

`retrieve_with_scores()` lit ensuite `metadata.get("relevance_score", 0.0)` pour exposer le score à l'UI.

---

## Pourquoi appliquer une sigmoid sur le score ?

`bge-reranker-v2-m3` retourne des **logits bruts** non normalisés (potentiellement très négatifs pour les chunks peu pertinents). Affichés tels quels :
- Les valeurs sont peu lisibles : `0.02`, `0.01`, `-3.4`, `0.00`
- L'utilisateur ne sait pas interpréter ces nombres

Avec sigmoid `1 / (1 + e^-x)` :
- Conversion en **probabilité [0, 1]** facile à lire
- Sigmoid est **strictement monotone** → le tri reste **identique** avant/après
- Valeurs typiques : `0.62`, `0.55`, `0.50`, `0.04`

## Alternatives considérées

| Option | Pour | Contre | Décision |
|--------|------|--------|----------|
| **Subclass `CrossEncoderReranker`** | Minimal, propre, monkey-patch zéro | Couplage à une API privée upstream | ✅ Choisi |
| Wrapper qui rejoue le rerank manuellement après `retriever.invoke()` | Aucun couplage upstream | Double inférence cross-encoder = +50% latence | ❌ |
| PR upstream à LangChain | Solution propre long-terme | Pas le temps avant la soutenance | À faire en V2 |
| Fork de LangChain | Robuste | Maintenance lourde, overkill pour 5 lignes | ❌ |
